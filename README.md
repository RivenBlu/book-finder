# Book Finder

A personal, single-user tool that interviews you (mostly closed questions, always with an "Other / my own words" box), builds a readers'-advisory brief, researches real data on every candidate, and recommends 3 to 5 books for you *right now*, with honest reasons and what real readers complained about.

Runs locally on Windows with Node 24. Uses your **Claude Max** login through the Claude Agent SDK; no API key, no per-token billing.

## Run

```
start.cmd
```

or `npm start`, then open http://localhost:3737. Data lives in `data/bookfinder.db` (SQLite). Back it up by copying the file.

Requirements: Node 22.13+ (24 installed), Claude Code CLI logged in (`claude auth status`). Do **not** set `ANTHROPIC_API_KEY` in your environment or the app will bill an API key instead of using the subscription.

## How it works

1. **Taste profile** (once, editable): loved books and *why*, abandoned books and *why*, "doorway" (story/character/setting/language/ideas), pace and prose preference, feel-vs-think, dealbreakers (hard filters), turn-offs (soft penalties), languages, formats, films/series/games as taste proxies.
2. **Check-in** (every session, ~12 closed questions): mood, what the book must *do* (distract / comfort / sit with it / thrill / think / laugh / awe / learn / feel), effort available, how you will read it, light-dark, safe-disturbing, familiar-strange, fiction/nonfiction, life context, last book, free-text itch. Quick mode asks 6.
3. **Adaptive follow-ups** (2-3, generated by Claude): resolves contradictions, "pick one of these two blurbs" pairs, clarifies your free text.
4. **Brief**: Claude translates everything into appeal terms (pace, tone, style, character, storyline, moods), constraints, hard excludes, anchors and anti-anchors, and designs the slate (safe bet, stretch, wildcard, short/comfort).
5. **Long list**: 12-22 real candidates, excluding everything you have read, shelved, been shown or rejected.
6. **Real data**: for each candidate, the Goodreads page (description, genres, rating distribution, the 30 most-liked real reviews), Open Library subjects, optional Hardcover crowd moods, and for Polish sessions lubimyczytac.pl ratings (1-10) and Polish reviews. Cached forever per book.
7. **Review digests**: Claude reads the real reviews per book: praise, complaints, who loves it, who should skip, how the first 100 pages read, content notes, verbatim quotes. Cached per book.
8. **Final slate**: 3-5 picks with slot, headline, "why now", what readers love and complain about, the single biggest risk *for you*, read-if / skip-if, how to approach the opening, plus runners-up and the candidates dropped after reading reviews (with reasons).

Every answer is stored with a timestamp. Trait answers are superseded, never overwritten, so drift stays visible. State answers (mood, need) are kept per session.

## Talking about a book

Every pick on a results page, and every book page, has **Ask about this book**: a conversation grounded in the real reviews, the digest, your profile and (on a results page) the rest of the slate. Starter questions cover the usual worries: how slow the opening is, how dark it gets, whether anything in it would bother you, comparisons with the other picks, Polish editions and audiobooks. Spoilers only when you ask for them. The conversation can look things up on the web for facts outside the reviews (editions, narrators, sequels); switch that off in Settings if you want faster answers. **Ask about these picks** on a results page talks about the whole slate.

## Should I read this?

"Check a book" (or the box on the home page) takes a title, fetches its real reviews, and gives a verdict against your whole profile including your latest check-in: Yes / Probably / Maybe / Probably not / No, a fit percentage, what you will love, what will bother you, the biggest risk, the best moment to read it, and sometimes a better alternative for the same itch. Verdicts are kept on the book page; "Judge again" after your taste or mood changes.

## Audio

If you answer "mostly as audio" or pick the audio format, the review digests note what readers said about the narration, the long list avoids books that depend on footnotes, maps or typography, and every pick carries an "As audio" line.

## Export

On a results page: **Copy as text** (Markdown, ready for a note or a message), **Download .md**, or **Print** for a clean sheet without buttons.

## Shelves and learning

System shelves: Reading now, Up next, Someday, Maybe, Finished, Did not finish, Not for me. Add custom shelves ("Beach", "For when sad", "Gifts"). Finished items take a rating and a verdict; DNF and Not-for-me take a reason. All of it feeds the **Reader DNA** rebuild (Reader DNA page), which infers stable patterns with confidence levels you can delete.

Import your **Goodreads** or **StoryGraph** export CSV (History page) or any CSV with Title, Author, Rating columns. Imports are never recommended again.

The Reader DNA also **rebuilds itself once a week** while the app is running, but only when there is new evidence (answers, shelf verdicts, history, feedback). Switch it off in Settings. The Reader DNA page shows **Mood over time**: effort, light/dark and safe/disturbing per check-in as small charts, with the mood and need in words, plus a few plain-language patterns (what you most often arrive as, what you ask for on harder days).

## Using it

- One question per screen. Press 1 to 9 to answer, Enter to continue, Backspace or the Back button to go back. Single-choice questions advance by themselves; multi-choice and free text wait for Continue.
- "Other / my own words" is under every question and is read as the strongest signal.
- Light theme by default; the circle in the header switches to dark.
- Covers are fetched through the app and cached in `data/covers`, so they load even when the image host is slow.

## Settings

Per-step model tiers (fast = Haiku, smart = Sonnet, best = Opus, max = Fable) including conversations and verdicts, web search on/off for the candidate step and for conversations, weekly automatic Reader DNA rebuild on/off, number of adaptive questions, optional Hardcover API token. A full run takes roughly 4-7 minutes with the defaults; the progress page updates live and you can leave it.

## Security and privacy

- The server binds to `127.0.0.1` only and has no accounts: anyone who can run programs on your computer can use it. Do not expose the port (no port-forwarding, no `0.0.0.0`).
- The API refuses state-changing requests that carry a foreign `Origin` or `Referer`, and accepts JSON bodies only, so a web page you happen to visit cannot drive the app through your browser.
- The cover proxy fetches `https` image URLs only, refuses private and loopback hosts, refuses redirects that land on a private host, and keeps only responses that are images.
- Everything personal lives in `data/` (database, cached covers, settings including an optional Hardcover token). That folder is git-ignored; never commit it. Back it up by copying the file.
- The model is called through your own Claude Code login; nothing is sent anywhere except Anthropic (your answers and the review material for the book in question), Goodreads, Open Library, lubimyczytac.pl and Hardcover (searches and book pages), and the web search the model may run for a conversation.
- This repository contains no reader data. To report a security problem, open an issue.

## Data sources and their terms

- Open Library (free API, polite rate) for search and metadata.
- Goodreads pages for reviews and rating spreads. There is no Goodreads API; this reads the public page's embedded JSON. Goodreads' terms disallow automated gathering, so this is personal, low-volume (one page per book, cached), and it may break if the page layout changes.
- lubimyczytac.pl (Polish) likewise: public page JSON-LD, personal use, same caveat.
- Hardcover.app: optional, sanctioned for personal use, needs a free token.
